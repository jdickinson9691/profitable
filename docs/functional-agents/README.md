# Profitable — Functional Agent Contracts

A second, **feature-organized** companion to `docs/agents/` — that folder's 55 files remain the authoritative historical record of *how the game was built* (chronological, by phase: MVP → Phase 2-5 → Galactic Map → Travel Encounters → Scanner → Combat → Alpha Content → Unity Migration). Nothing there is renamed, renumbered, or rewritten by this folder.

This folder answers a different question: **"what's the current contract for Crafting?"** (or Mining, or Travel, or any other single system) — a question the phase-based roster answers by scattering the answer across several files (e.g. Crafting's formula lives in Agent 2, its content in Agent 6/14/23, its UI in Agent 5). Each file here consolidates one feature area's *current* contract — real functions, types, constants, and file paths, verified against the source, not paraphrased from memory — into one place, and becomes the reference for any future work on that system, in the same `Responsibility → Inputs → Outputs → Must NOT Do → Testing Requirements → Definition of Done` shape the phase-based contracts already established.

**Four files here are genuinely new scope, not a consolidation:** [`ship.md`](ship.md) — a Ship status screen plus three mechanics locked via a new design pass, **fully built, no known gaps**: **Ship Fuel**, **Cargo Hold Capacity** (both fully built), and **Ship Crew Roles** (all 5 role effects built, including Systems Engineer's repair effect, task #89, and a real `> Unassign` action) (see `profitable-design-questions.md`'s sections of the same names for the full decision record) — [`universe.md`](universe.md) — a fully-designed but entirely unbuilt multiplayer economy/leaderboard layer (`profitable-design-questions.md`'s Multiplayer section), deliberately unscheduled — [`planet-ownership.md`](planet-ownership.md) — **Colonist-Driven Production** (built) **and Citadels** (claim/build, refuel discount, and depth-scaled repair all built — Level 2's original "cargo storage" benefit was repurposed into a reduced repair tier, see that file for why), found via the TradeWars alignment review below — and [`build.md`](build.md) — **structurally different from the other three, and from every file in this folder**: not a game system, but the meta-agent that sequences and runs the Unity-migration porting agents, gated on each area's actual TypeScript-build status per this folder's own Status lines. See that file's own opening note before reading it as a game contract.

**Former gap, now closed:** Ship Crew Roles extends the existing crew system (`CrewMember`, hire/wage/upkeep/attrition) — that system now has its own consolidated contract, [`crew.md`](crew.md), rather than being documented only in `docs/agents/agent-16-crew-core.md`'s phase-based record. `ship.md`'s Crew Roles section reads from `crew.md`'s system without duplicating it. `BACKGROUND_IDLE_OUTPUT_RATE`, previously flagged as `null`/inert, is now resolved (0.5/hour) with real inventory consumption wired into `CrewScene`'s `> Check Background` action. `CREW_POOL_REFRESH_INTERVAL_HOURS`, previously a no-op tunable, now correctly re-rolls a stale crew pool — the same fix applied to the shipyard/scanner pools' identical gap (`travel.md`).

**See also `docs/profitable-tradewars-alignment.md`** — a research/comparison pass against TradeWars 2000/2002 (this project's confirmed foundational gameplay-loop inspiration). It found one verified, real gap in `planetary-markets.md`'s current implementation (single-player trading has no permanent counterparty past the seed-market listings) — fixed as the **Trading Counterparty** section (`sellToMarket()`/`sellToGlobalMarket()`, both now built) — plus **Colonist-Driven Production**/**Citadels** (now `planet-ownership.md`, above). Reputation/alignment and a couple of minor items (haggling, a StarDock-style hub) were reviewed and deliberately parked, not pursued.

**Two more files were existing systems changed by newly-locked design, now built:** [`planet.md`](planet.md) gained fixed per-resource quality, a live-derived resource reset cycle, and a starting-planet tutorial guarantee (`profitable-design-questions.md`'s "Planet Resource Generation" entry) — and [`mining.md`](mining.md) (renamed from "Gathering" — terminology only, the underlying code still says `GatherScene`/`gather`, see that file's own note) lost its own quality-rolling call site as a direct consequence, becoming a deterministic read of whatever `planet.md` fixes. Both deliberately reopened previously-"resolved" design, recorded as such rather than silently changed. Most other files below document an already-built, already-verified system with no pending change; a few (`planet-ownership.md`, `ship.md`, `universe.md`) still have real unbuilt scope, see below.

## Relationship to the phase-based roster

- **This folder is additive, not a replacement.** `docs/agents/README.md`'s Creation Order and Cross-Cutting Rules remain in force exactly as written — nothing here overrides them.
- **When a system changes going forward**, the corresponding file here is the first thing to read and the first thing to update — not because the phase-based agent that originally built the system stops mattering, but because this file is where its *current* contract lives, kept in sync with the real code rather than frozen at whatever phase first shipped it.
- **A change here still needs a real amendment contract before implementation**, same discipline as every phase since MVP. This folder describes contracts; it doesn't grant license to skip writing one before touching code (see Alpha Content Authoring's own retroactive-amendment story in `docs/agents/README.md` for what happens when that discipline slips).

## Cross-cutting rules (restated from `docs/agents/README.md`, not re-litigated)

These apply to every file in this folder exactly as they apply to every file in `docs/agents/`:

- No file hardcodes a number that already exists in a constant table elsewhere — a value changes in exactly one place.
- No file reaches "downward" past its declared inputs — presentation calls core's public functions only, never core's private helpers, never another system's raw content JSON directly.
- Simulation code stays framework-agnostic (no Phaser/DOM imports) — the hard boundary this entire project is built around, restated once per file below rather than assumed.
- A gap or mismatch found between two systems is an integration bug, reported and attributed to the responsible system — never silently patched around by whichever file's author hits it first.
- Nothing in this folder implements a mechanic already explicitly deferred elsewhere (multiplayer market manipulation detection, real-time position tracking, a fifth ship component, etc.) — see `profitable-design-questions.md` for the full list of what's deliberately not built and why.
