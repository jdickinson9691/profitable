# Agent 39: Unity Galaxy/Planet Simulation Core Agent

**Creation order:** Second in Migration Phase 2, Sub-Phase A. Depends on Agent 38 (Unity Galaxy/Planet Schema). Agent 40 (Unity Galaxy/Planet Parity Validation) is created alongside this agent and runs continuously against it, same pattern as Agent 32/33's original relationship.

## Responsibility

Port `galaxy.md`/`planet.md`/`mining.md`'s current formula logic to C#: seeded determinism, galaxy/planet generation, resource-subset selection, planet-modified quality rolling, and the live resource-reset cycle (including the starting-planet tutorial guarantee) — exactly, per `profitable-unity-migration-gdd.md` Section 1's port-vs-rewrite rule. Mining itself (`mining.md`) contributes no new formula of its own to port here — it already reads exclusively through `GetCurrentPlanetResources()`, this agent's own output, per that file's "read whatever `planet.md` already fixed for this resource on this planet, right now" contract.

## Inputs

- `docs/agents/agent-38-unity-galaxy-planet-schema.md` — the types/constants this agent builds against.
- `docs/functional-agents/galaxy.md`, `planet.md`, `mining.md` — current, as-built consolidated contracts.
- The current TypeScript source, in full:
  - `src/galaxy/seededRandom.ts`, `generateGalaxy.ts`, `generatePlanet.ts`, `resourceSubset.ts`, `rollQualityOnPlanet.ts`, `planetResourceCycle.ts`.
  - `src/simulation/aggregateTier.ts` — a necessary completion (see Outputs Section 1): needed by the tutorial-guarantee logic this agent ports, not previously in scope for Migration Phase 1's MVP loop.
  - Test fixtures/cases for parity: `tests/galaxy/*.test.ts`, `tests/planets/*.test.ts` covering generation, resource-cycle determinism, and the tutorial guarantee.

## Outputs

### 1. Necessary Schema/Simulation completion: `ComputeAggregateTier`

`src/simulation/aggregateTier.ts` was not part of Migration Phase 1's ported scope (the MVP loop's `Refine`/`Craft` compute their own output tier inline, never needing a standalone reusable aggregate-tier function). Sub-Phase A's tutorial-guarantee logic has a hard dependency on it, so it is added here rather than left as a silent gap — same "necessary completion, documented not silent" pattern Agent 32 already used for `ResourceInstance`/`RefineResult`/`CraftResult`/`RandomFn`. `ComputeAggregateTier(QualityMap): TierColor?` — straight average of the qualities that aren't `null`, resolved through the already-ported `TierColorResolver.GetTierColor`; returns `null` (not a thrown exception) when every quality is `null`, matching the TypeScript source's own `null`-returning contract exactly (this is the one place in the ported formula layer where "no valid tier" is a real, expected outcome rather than a caller error).

### 2. `Profitable.Core.Simulation` namespace

- `SeededRandom.Create(string seed): RandomFn` and `SeededRandom.GenerateSeed(): string` — the djb2-style string-hash-into-mulberry32 PRNG, ported bit-for-bit (the exact bitwise operations, not a re-derived "equivalent" PRNG — a different-but-plausible PRNG would silently break every seed-reproducibility guarantee this whole layer depends on). `GenerateSeed()` is the one place true non-seeded randomness is appropriate, matching the TypeScript source's own carve-out.
- `PlanetGenerator.RollPlanetTier(RandomFn): TierColor`, `ChoosePlanetType(RandomFn): PlanetType`, `Generate(string seed, PlanetPosition, IReadOnlyList<Resource>): Planet` — tier/type roll on the base seed stream, resource generation delegated to `PlanetResourceCycle.GenerateResourcesForCycle` at cycle index 0, exactly mirroring the TypeScript source's own call-into-shared-logic structure (never a second, duplicate copy of subset selection).
- `ResourceSubsetSelector.GetEligibleResources(PlanetType, IReadOnlyList<Resource>): IReadOnlyList<Resource>` — case-insensitive substring match against the broad category vocabulary, **plus the `ItemTier == 1` requirement** (the real bug fix found auditing the alpha content roster: a self-referential refined/crafted resource's own id-as-category string can accidentally contain a broad category substring, e.g. `"master-crystal-array"` contains `"crystal"` — ported as a hard requirement, not an incidental detail, since it's a real correctness fix, not stylistic). `ComputeSubsetCount(TierColor, int eligibleCount): int` — `max(1, ceil(percentage * eligibleCount))`. `SelectResourceSubset(...): (List<string> ProducibleResourceIds, string? SpecialtyResourceId)` — the reserved-slot rule: White-tier-or-higher planets pick a specialty first (occupying one of the `count` slots, never inflating it), Grey-tier planets never get one.
- `PlanetQualityRoller.RollQualityOnPlanet(Resource, TierColor? tier, string? specialtyResourceId, RandomFn?): QualityMap` — wraps the already-ported `QualityRoller.RollQuality` (never modifies or duplicates it), adds the planet tier modifier plus specialty bonus (if applicable) to each non-null dimension, clamps back to 1-100. A `null` tier applies no modifier at all (safe to call on any planet).
- `PlanetResourceCycle.GetCycleIndex(string planetId, long nowMs): int` — the seeded phase-offset-then-floor-divide technique, zero persisted state, a pure function of `(planetId, now)`. `GenerateResourcesForCycle(string seed, TierColor, PlanetType, IReadOnlyList<Resource>, int cycleIndex): ResourcesForCycle` (a new small record type: `ProducibleResourceIds`, `SpecialtyResourceId`, `ResourceQualities`) — one shared implementation `PlanetGenerator.Generate` (cycle 0) and `GetCurrentPlanetResources` (below, any live cycle) both call, never two copies. `GetCurrentPlanetResources(Planet, IReadOnlyList<Resource>, long nowMs, bool isStartingPlanet = false): ResourcesForCycle` — the colonist gate (`Planet.ColonistCount ?? 0 < MinimumColonistsToProduce` returns empty) is the first check, before tier/type are even read; throws if `Tier`/`PlanetType` are missing on an otherwise-colonized planet, matching the TypeScript source's own explicit throw.
- The starting-planet tutorial guarantee (private to `PlanetResourceCycle`, exposed only through `isStartingPlanet`): a direct, closed-form override on a fresh, independently-seeded random stream (never continuing the resource-selection stream) — adds any of the 3 guaranteed resource ids missing from the natural draw, then clamps every dimension of each guaranteed resource to `TutorialGuaranteeQualityClamp` if its aggregate tier (via `ComputeAggregateTier`, above) would otherwise exceed White. Reapplied every cycle, including every reset — never a one-time bootstrap.
- `GalaxyGenerator.Generate(int planetCount, IReadOnlyList<Resource>, string? seed = null): Galaxy` — a fixed, finite set of planets generated once; positions drawn from their own independent random stream (`{seed}:positions`) so generating positions never perturbs any individual planet's own tier/type/subset/specialty rolls.

## Must NOT Do

- Must not implement any Trading/Crew/Ship/Planet-Ownership/Combat logic — later Sub-Phases' scope, exactly mirroring how `planet.md` itself only reaches into `planetOwnership.ts` for the one `MinimumColonistsToProduce` constant, never Citadel/refuel behavior.
- Must not re-derive `SeededRandom`'s PRNG from a different (even if statistically equivalent) algorithm — the exact bitwise hash-then-mulberry32 sequence is what every seed-reproducibility guarantee in this layer depends on; a "cleaner" reimplementation would silently break parity for every generation function built on top of it.
- Must not duplicate resource-subset-selection logic between `PlanetGenerator.Generate` and `PlanetResourceCycle.GenerateResourcesForCycle` — one shared implementation, called at cycle index 0 for the former, exactly mirroring the TypeScript source's own refactor history (this exact duplication was factored out during the Planet Resource Generation amendment specifically to avoid two copies of the same formula).
- Must not implement rendering, input handling, save/load, or audio, or reference the Unity Editor/engine APIs at all — this agent's output must keep building via `dotnet build`/`dotnet test` alone.
- Must not re-derive `ItemTier == 1`'s eligibility requirement, the reserved-slot specialty rule, or the tutorial-guarantee's clamp-to-White logic from GDD prose instead of the current TypeScript source — each is a real, previously-found bug fix or design decision, not an obvious re-derivation.

## Testing Requirements

- Unit tests (xUnit) mirroring the TypeScript suite case-for-case: `SeededRandom` determinism (same seed → same sequence); `GalaxyGenerator.Generate` determinism (same seed → identical galaxy, confirmed via a deep equality check, the exact regression case `tests/galaxy/regressionCheck.test.ts` already proves in TypeScript); `ResourceSubsetSelector`'s reserved-slot rule (a White+ planet's specialty never displaced by the general draw, a Grey planet never gets one); the `ItemTier == 1` eligibility fix (a synthetic resource whose category string collides with a broad category substring is correctly excluded); `PlanetQualityRoller`'s tier/specialty modifier stacking and clamping; `PlanetResourceCycle.GetCurrentPlanetResources`'s colonist gate, cycle determinism (mining the same resource from the same planet twice in the same cycle returns identical quality), and reset-cycle-boundary divergence (crossing into a new cycle changes the result).
- A dedicated tutorial-guarantee test suite: the starting planet always includes all 3 guaranteed resources at Grey/White aggregate tier, verified across many seeds and across several simulated reset cycles (not just cycle 0) — mirroring `planet.md`'s own flagged testing requirement that this idempotency claim needs a real multi-cycle test. A non-starting planet (including `secondaryDiscoveredPlanet`, once Agent 41/42 wire it in) must not receive this override under the same conditions.
- Regression: `Refine`/`Craft`/`RollQuality`/`GetTierColor` (Agent 32) are provably unaffected by anything in this agent — confirmed via their own existing test suites passing unmodified.
